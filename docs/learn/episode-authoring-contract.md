# SINGA WORLD 各話制作契約

この文書は、完成後の言い換え集ではない。新しい人物・新しい話を作る前に埋める制作契約である。
禁止語を増やして文章を縛るのではなく、受け手の中で起こす変化と、そこへ至る因果を先に固定する。

## 1. 中心質問は一つ

- `primaryQuestion`: この回を開いた人が、最後までに答えを知りたい一つの問い。
- 問題、学ぶ手段、知りたい変化がこの一文だけで分かるか確認する。
- 主見出しだけで意味が通るなら、説明的な副質問は置かない。
- 副質問が必要な場合だけ、主見出しでは欠ける前提を `adds` に書く。言い換え、要約、抽象化は追加理由にならない。

例：

> 『やらなきゃ』と思うほど動けない時、催眠をどう使う？

この問いは一文で成立するため、「できない自分へ命令する代わりに何へ注意を向ける？」を重ねない。

## 2. 一つの台詞は、一つだけ前へ進める

台詞を書く前に、その台詞の役割を一つ選ぶ。

- 問う
- 直前の出来事を言い直す
- 違和感を出す
- 相手の答えを受け取る
- 次の行動へ誘う
- 発見へ名前を付ける

一つの台詞で、説明、予告、手順、専門語を同時に渡さない。特に選択後は、選んだ内容を受け取り「次に何を一緒にするか」だけを返す。

## 3. 対話は入力回数ではなく、往復で設計する

アドベンチャーの基本リズムは次の通り。

1. **記憶**：証拠を見る前に、覚えていることをリンクへ話す。
2. **確認**：リンクの疑問に沿って、必要な場面を一つずつ見る。
3. **仮説**：見終えた後、違いをどう考えたかリンクへ一言で話す。
4. **応答**：リンクが本人の言葉を引用し、次の問いを生む。
5. **判断**：仮説を持ったまま、プレイヤーが推理を選ぶ。
6. **応用**：自分か相手へ一手を使い、その反応を受け取る。

証拠をタップさせるだけ、三択を選ばせるだけでは対話と数えない。入力した言葉が次の人物の台詞へ残って初めて一往復である。

選択肢は「正解を当てるボタン」ではない。誤った一手を選んだ場合も、相手に何が起きたかを台詞で返し、なぜ進まなかったのかを体験させる。正しい一手では、結果だけを説明せず、催眠が進むところまで人物の反応を見せる。

技法名を教える順番は次で固定する。

1. プレイヤーが一手を選ぶ。
2. 人物に変化が起きるところまで見せる。
3. 「なぜ変わったと思う？」を、プレイヤーの言葉で答えてもらう。
4. その答えを人物が受け取る。
5. 先生が因果を説明し、最後に技法名を付ける。
6. 同じ因果を、プレイヤー自身の問題へ応用する。

## 4. 支援は話数と成長に合わせて外す

- `full-example`: 第1話など。答え方が分からない人へ、具体的な回答例を一つ見せる。
- `partial-cue`: 中盤。見る観点だけ示し、答えそのものは書かない。
- `independent`: 習得後。例を置かず、自分の記憶・仮説で答える。

例文に答えが近いこと自体を禁止しない。なぜ今その支援量なのか説明できるようにする。同じ支援を全30話で固定しない。

## 5. 入力方法と完了条件を同じ設計にする

「三択か自由記述のどちらでもよい」と書くなら、UIもどちらか一方で送信できなければならない。

- `choice-required`: 選択が学習上必要。
- `detail-required`: 本人の言葉が学習上必要。
- `choice-or-detail`: 選択または自由記述のどちらかで進める。

録音、記述、選択は入力手段であり、学習目的ではない。スマホのキーボードが開いても、入力欄の近くに送信操作が見えることを確認する。

## 6. 発見画面では、もう一度授業をしない

発見画面の役割は、いま体験した変化へ短い名前を付けること。

- 中央：発見の見出し
- 左寄せ：句点ごとに分けた短い説明
- 最後：次に進む操作

直前に見た証拠一覧、次章の説明、別の問いを同じ画面へ重ねない。必要な証拠再掲がある場合は、なぜ再掲しないと理解できないかを先に記録する。

## 7. 表示は文章の役割に合わせる

- 大見出しは中央寄せでもよい。
- 説明文と台詞は左寄せにする。
- 二文以上ある説明は句点ごとに行を分ける。
- 単語の途中に意図的な改行を入れない。改行位置は文章の意味で決め、端末幅による折り返しはUIへ任せる。
- 英語の技法名を初めて見せる時は、日本語の読みを併記する。
- スマホ一画面に、見出し・本文・主操作が同時に見えるか確認する。

## 8. 次回予告は一画面の事件フックにする

終了後に縦スクロールさせて次回説明を読ませない。次回の相手、対立する一言、先生の意外な返答、解放条件を一画面へ収める。第1話の結論をもう一度説明せず、「次はどうなる？」だけを残す。

## 9. 実装前と実装後を分けて確認する

### 実装前

- 全文をテキストだけで読み、物語として続きを知りたいか。
- 各台詞が、前の出来事がなければ発生しない台詞になっているか。
- 初学者が「誰が、何を、なぜしているか」をその場で取り戻せるか。
- 主見出しだけで意味が通るのに、説明を足していないか。

### 実装後

- 文字、画像、ボタンがスマホ一画面で読めるか。
- 選択、記述、録音の各経路で本当に先へ進めるか。
- 不正解を選んだ時、相手の反応から間違いの理由が分かるか。
- 入力した内容が後の会話へ返るか。
- 発見画面と講義画面の役割が混ざっていないか。
- 体験で起きた変化を考える前に、先生が答えを言っていないか。
- 次回予告が縦スクロールなしの一画面に収まるか。

自動検査は必要条件を守るためのもの。面白さと自然な会話は、最初から最後まで実際に読み、操作して別途判定する。
