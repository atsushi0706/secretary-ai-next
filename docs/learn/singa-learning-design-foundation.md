# SINGA WORLD 学習体験の設計原則

## 何を設計するか

SINGA WORLDは、説明をゲーム風のUIに載せる教材ではない。
プレイヤーが自分で判断し、相手の反応を受け取り、理解と立場の両方が変わる学習アドベンチャーである。

台詞の禁止語や必須語からシナリオを作らない。最初に、次の因果を一続きで決める。

1. 学ぶ前の人は、日常のどんな場面で困っているか。
2. その人は、何を正しいと思って繰り返しているか。
3. その行動が、なぜ困難を強くしているか。
4. 先生のどんな経験と信念が、別の判断を生むか。
5. 注意・解釈・行動のどれを、どこからどこへ移すか。
6. プレイヤーは何を自分で選び、相手から何が返るか。
7. 日常のどの場面で、次に何を一つ試せるようになるか。
8. その結果、物語の中で何者から何者へ変わるか。

この因果が通ってから、漫画、会話、選択肢、講義、カード、UIを作る。

## ユーザーの設計思考を言語化する

ユーザーは、言葉を「正しい説明か」だけで見ていない。その言葉を受け取った人の頭の中を一秒ずつ再生し、前提、因果、行動がつながるかを見ている。

特に次の判断を同時に行っている。

1. **省かれた前提を見つける。** 「今できることを使う」と聞いた時、その前に「なぜ今の方法をやめる必要があるのか」が抜けていると気づく。
2. **分類語と変化の過程を分ける。** 「使える感覚」は材料の名前であり、学びそのものではない。学びは、どこへ囚われていた注意を、なぜ、どこへ移したかという変化である。
3. **本人の内側の前提まで読む。** 「やらなきゃ」という言葉の奥に、「今できないことを、同じやり方で今すぐ成功させなければならない」という自己暗示があると読む。
4. **因果の中間を飛ばさない。** 「地面や風をイメージした」から「体が動いた」へ直行せず、できない足から目が外れ、動けていた体験へ注意が移った、という中間を必要とする。
5. **日常での使いどころまで戻す。** 原理を覚えるだけでなく、先延ばし、継続、怖さの場面で、次に何を一つするかまでつなぐ。
6. **受け手のつまずきを品質基準にする。** 作り手が補完できるかではなく、前提知識がなく前後を忘れやすい人が、その画面だけで意味を取り戻せるかを基準にする。

AIが以前ここを落としたのは、Utilizationを「今ある反応を利用する」という短い定義へ圧縮し、その定義に合う語を配置することを優先したためである。その結果、定義に至る前の心理状態、失敗が続く理由、注意を外す必然性を省略した。以後は、短いコピーを先に作らず、`囚われている方向 → そのため続く失敗 → 目を外す → 移す先 → 次の一手`を先に書く。

## 清瀬淳の四つの判断軸

第1話を含む全話は、実装者の目だけで合格にしない。清瀬淳が実際に行っている次の四つの判断を、別々に通す。

1. **学習のプロ。** 初学者の認知負荷、前提知識、記憶の途切れを見て、その画面だけで現在地と目的を取り戻せるかを判定する。
2. **意味を通す人。** 主語、対象、理由、変化、結果の間に飛躍がないかを見る。「言っている内容」ではなく「なぜ今それを言うのか」まで通す。
3. **感情と面白さを判断する人。** 正しい説明でも、驚き、葛藤、発見、次を知りたい気持ちが生まれなければ不合格にする。
4. **コールドトラフィックをHOTにするコピーライター。** まだエリクソンもUtilizationも知らない人の現在の悩みから入り、「自分のことだ」「なぜ？」を起こし、体験を通して専門テーマへの関心を温める。

四つは混ぜて一度に採点しない。学習として分かりやすくても退屈なら不合格。面白くても因果が飛んでいれば不合格。専門家に通じても、コールドの人が入口で離れれば不合格である。

## 「意味の一本道」

初学者は前の画面を覚えているとは限らない。各画面は単独で読めるだけでなく、前の画面から生まれ、次の画面を必要とする形にする。

- 目的：これは何の問題を扱うのか。
- 現在地：誰が、何をしているのか。
- 理由：なぜ今、それを見る・聞く・選ぶのか。
- 結果：その選択で、相手や状況がどう変わったのか。
- 名前：体験したことを、最後に専門語で整理する。
- 転用：自分の日常で、いつ何を試すのか。

途中の一つを省くと、言葉そのものは読めても「なぜ今これを言うのか」が分からなくなる。

## 作り手が毎回行う二種類の確認

### 個別画面の確認

- 主語と対象が書かれているか。
- 抽象語を、目に見える言動へ直せるか。
- 一つの台詞が一つの役割だけを持つか。
- ボタンを押した結果が、その場で分かるか。
- 文字、人物、背景、操作がスマホ一画面で読めるか。

### 最初から最後までの通し確認

- 冒頭で約束した学びを、最後に回収しているか。
- 前の出来事が、次の台詞を発生させているか。
- 主人公の選択が、後半の会話と結末へ残っているか。
- 漫画、捜査、講義、日常応用が同じ因果を別の言い方で扱っているか。
- 途中で別のテーマや古い仕様へ戻っていないか。
- 「もっと知りたい」と思う未解決の具体的な問いが残るか。

個別画面が合格でも、通しの物語が合格とは限らない。両方を別々に記録する。

## 読者・登場人物・作り手の視点

### 初学者

前提知識がなく、前の画面を忘れても、誰が何をなぜしているか追えること。

### 清瀬リンク

用語を復唱する係ではない。「それが催眠とどうつながるの？」「ただ目標を小さくするのと何が違うの？」と、読者が離脱する直前の疑問を具体的に言う。先生の説明を美しく要約するより、初学者の違和感、驚き、反論を先に出す。

### 先生

一般論を説明する装置ではない。本人の経験、信念、目の前の相手の状態から、次の一言を選ぶ。

### プレイヤー

正解ボタンを押す観客ではない。先生の答えを見る前に一手を決め、その結果を相手から受け取り、後半で自分の判断として回収される。

### 作家・漫画家・ゲーム制作者

作家は因果と興味を、漫画家は視線誘導と時間の流れを、ゲーム制作者は操作と反応を確認する。最後に、三つを一つの体験として通して確認する。

## 自動生成の順番

1. 学習者の日常の困りごと
2. 困りごとを強めている前提・自己暗示・行動
3. 先生の具体的な事件
4. 事件の前後で変わったもの
5. 初学者が本当に抱く疑問
6. プレイヤーの判断と相手の反応
7. 因果を整理する講義
8. 自分の日常への一手
9. 専門語と原理カード
10. 主人公の変化と次の物語

工程数を守ることが目的ではない。各画面は、上の因果に必要な時だけ置く。

## AIによる質問回答

質問への最初の一文で答える。その後、現在地の出来事と本人が選んだ内容を使って説明する。

回答は必ず、必要に応じて次を明らかにする。

- いま何へ注意が固定されているか。
- なぜそれが問題を続けているか。
- 何から目を外すのか。
- 何へ注意を移すのか。
- 次に何を一つするのか。

本人の悩みを診断しない。医療効果を断定しない。まだ見ていない物語の答えを先に出さない。保存された質問と回答は、本人の学習メモとして後から読めるようにする。

## 品質の事実表示

AIが役割を想定して読むことと、実在する人がテストすることは別である。

- 模擬チェックは、誰の視点で何を確認し、何が不合格だったかを書く。
- 実ユーザー試験は、実際の参加人数と観察結果を書く。
- 実在ユーザーが0人なら、合格人数を作らない。
- 自動検査だけで「面白い」「分かりやすい」と断定しない。
